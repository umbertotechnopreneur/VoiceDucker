# VoiceDucker 0.2.0

Since 0.1.1, I improved volume restoration, Windows integration and resource
handling, and integrated the two outstanding pull requests.

## What changed

- I now listen to native Windows audio-session volume and mute events, even when
  microphone monitoring is off. I distinguish my own mixer writes from external
  changes without blocking the Windows callback thread.
- I improved the ducking/fade algorithm and interrupted fade recovery. Each
  session keeps its startup volume baseline for the app's lifetime, including
  across Disable/Enable and external mixer changes. New sessions get their own
  baseline when first observed. Muted and silent sessions are left alone.
- I release expired session handles during monitoring. Closing stops UI timers,
  unregisters callbacks and releases audio resources, with restoration failures
  reported instead of silently claiming success.
- I integrated PR #9: Store license/trial handling, About disclosures, legal
  links and footer links that fade after 30 seconds and return on hover or focus.
  Portable and local development builds remain unrestricted and MIT-licensed.
- I integrated PR #10: corrected WinGet archive/PATH instructions so the app host
  can find its companion DLLs. This release does not submit or publish WinGet.
- I reviewed microphone privacy, opt-in local diagnostics and resource lifetime.
  I reuse completed Defender first-import evidence for identical dependency
  archives and verify SHA-256 hashes before compilation. New or changed imports
  require their own targeted scans. Builds and tests do not run antivirus scans.

## Validation boundaries

Windows x64 and ARM64 packages are compiled from the repository source. The
release includes archive checksums and dependency-evidence verification reports.
Those reports cite prior completed scans; they are not new scans of this release
and do not certify that the application is free of security vulnerabilities.

The completed local checks passed for settings and license policy, window
placement, single-instance handling, playback restoration and event filtering.
The native Windows callback check passed for own/external EventContext, volume,
mute, unmute and callback removal, affecting only its own silent session.

The resource test used 100 warmup plus 1,000 native subscribe/dispose cycles.
After collection, no subscription objects remained rooted. Managed memory was
296,864 to 329,248 bytes, private memory 10,649,600 to 15,024,128 bytes, and
process handles 358 to 360. These are test-harness measurements, not full-app RAM
or proof of constant memory use. Startup baselines intentionally retain one
scalar entry per observed session until exit.

NuGet's current vulnerability audit reported no known vulnerable direct or
transitive packages. I verified dependency/runtime archive hashes against
completed first-import scan evidence from 0.1.1. This does not establish absence
of unknown vulnerabilities.

No interactive microphone/playback test, ARM64 hardware test or Store purchase
test is implied. Memory/resource checks do not prove absence of all leaks.

## Downloads

Extract the entire x64 or ARM64 ZIP and open `VoiceDucker.exe`. Keep its companion
files together. The portable distribution needs no installer, starts with the
microphone off and is unsigned. This release does not update Microsoft Store.
